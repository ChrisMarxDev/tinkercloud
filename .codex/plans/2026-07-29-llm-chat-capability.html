Logic and Data Flow

SDK POST /_tinker/api/v1/llm/chat
→ gateway derives app/viewer and issues sealed AuthorizationContext
→ strict route/origin/version/body validation
→ resolve active app grant and fixed operator profile
→ atomically reserve worst-case token budget + concurrency
→ decrypt key for one fixed-destination provider call
→ normalize bounded response
→ reconcile actual usage + append payload-free audit
→ return common chat response or stable typed error

State Model

Connection

validating → active ↔ disabled → revoked. Rotation validates and atomically activates a new credential version.

Grant

requested → approved ↔ disabled → revoked. Current server state is read on every invocation.

Invocation

admitted → reserved → calling → succeeded | failed | cancelled | ambiguous.

Chat controller

checking → ready → sending → complete | typed failure | cancelled. Prior messages stay visible.

Server truth owns credentials, grants, profiles, quota, and safe usage. The app owns any conversation history, optionally using existing KV.
