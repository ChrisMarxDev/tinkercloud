Rank 4 · Planned feature

The SDK is the app platform.

Give staff, non-technical deployers, and coding agents one small typed interface to identity, data, and every future TinyHost capability.

Low ceremony without weakening the server-side boundary.

Reason and value

Make the safe platform path the easiest path

Raw HTTP is useful as a contract but costly as an app-development interface. The Shopify Quick north star gives creators obvious operations, discoverable capabilities, strong types, and actionable errors while TinyHost continues deriving app and identity from the request.

Scope

  • Browser-first TypeScript and ESM package.
  • Current user, JSON KV, realtime, app info, and capability discovery.
  • Typed errors, cancellation, versions, and limits.
  • Framework-neutral, tree-shakeable runtime.
  • Executable examples and agent-skill integration.

Non-goals

  • No app ID, database credential, viewer token, or provider secret.
  • No framework-specific core API.
  • No offline database or client-side authorization claims.
  • No LLM/Jira adapter in the first SDK release.

Implementation sketch

Same-origin methods over versioned capabilities

import { tiny } from "@tinyhost/sdk";

const user = await tiny.user.current();
const item = await tiny.kv.get("reviews/42");
await tiny.kv.set("reviews/42", next, {
  expectedVersion: item?.version,
});

tiny.live.onKvChange({ prefix: "reviews/" }, refresh);
const enabled = await tiny.capabilities.list();

The SDK sends the app session cookie to reserved same-origin endpoints. TinyHost derives tenancy, authorizes, applies quotas, and returns typed safe errors.

Detailed SDK design

Implementation questions

  • Which Quick API conventions should be preserved versus adapted for per-app permissions and capability availability?
  • Handwritten types or generated transport types with a handwritten ergonomic facade?
  • Which WebSocket client library, if any, earns its dependency cost?
  • What compatibility range should the working package label expose?

Do or don’t

Ship it as core V1, not optional polish

Do: It materially reduces creator effort and gives every later capability a consistent, governable surface.

Don’t: Do not let convenience move authority or credentials into browser code.
