Rank 7 · Directional post-V1 feature

Use operator capabilities without revealing operator secrets.

Let apps invoke governed LLM, Jira, or internal-service operations through TinyHost while credentials stay on the server.

Invoke a grant; never deliver a secret to browser code.

Reason and value

Turn shared organizational access into safe building blocks

Operators already possess useful service credentials. Narrow server-side adapters could make them available to staff-built apps without handing deployers keys, duplicating backend code, or exposing unrestricted outbound access.

Impact5 / 5
Complexity5 / 5
Yield3 / 5

Scope

  • Operator-managed encrypted connections.
  • Explicit app grants, operations, resource scopes, and budgets.
  • Narrow typed SDK adapters beginning with one LLM provider.
  • Outbound destination control, quotas, redaction, and audit.
  • Immediate disable and secret rotation without redeploy.

Non-goals

  • No raw secret delivery to static apps.
  • No unrestricted authenticated HTTP proxy.
  • No arbitrary shell or unreviewed in-process plugins.
  • No external provider adapter in V1.

Implementation sketch

Server-side invocation pipeline

tiny.llm.generate(request)
  → authenticate viewer + resolve app
  → load effective capability grant
  → validate operation, budget, and payload
  → resolve encrypted operator connection
  → call allowlisted provider adapter
  → redact, audit, and return bounded result

Open questions

  • Grant scope: deployer, app, viewer, or combinations?
  • Cost budgets and human confirmation for consequential operations?
  • First adapter: LLM generation or an internal schema-bound API?
  • How can custom adapters preserve single-binary simplicity?

Do or don’t

Preserve the direction; defer implementation

Do: Design SDK capability discovery now so the future extension is natural and high value.

Don’t: Implement secrets or provider calls until the gateway, SDK, KV, realtime, quotas, audit, and operator grants are proven.

Directional feature; keep behind a separate post-V1 security gate.
