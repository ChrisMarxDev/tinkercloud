Implemented post-V1 L1/L2 capability

Give private apps chat, not API keys.

Let an operator connect Anthropic or Gemini, approve one app binding, and give deployers a small provider-neutral chat API while every credential stays behind TinyHost.

Invoke an approved chat profile; never deliver a secret, provider URL, or unrestricted model selector to browser code.

Reason and value

Make a useful chat UI possible without adding an app backend

Operators already possess LLM credentials, while deployers need only a safe chat operation. A narrow server-side adapter removes repeated backend work without handing keys to static bundles, viewers, or deployers and without creating unrestricted outbound access.

Scope

  • Write-only Anthropic and Gemini connections encrypted at rest.
  • One operator-approved model profile and grant per app.
  • Implemented bounded tiny.llm.chat.complete; streaming remains deferred L3.
  • Fixed destinations, token reservations, rate limits, redaction, and safe usage audit.
  • Immediate disable and secret rotation without redeploy.

Non-goals

  • No raw secret delivery to static apps.
  • No unrestricted authenticated HTTP proxy.
  • No arbitrary shell or unreviewed in-process plugins.
  • No tools, embeddings, files, images, web search, or stored chat history in the first slice.
  • Not part of the locked V1 release or its acceptance claim.

Implemented L1/L2 pipeline

Server-side invocation pipeline

tiny.llm.chat.complete({ messages })
  → authenticate viewer + resolve app
  → load current operator-approved app grant
  → validate payload and atomically reserve token budget
  → decrypt the bound connection for one call
  → call a fixed Anthropic or Gemini destination
  → reconcile usage, audit safe metadata, return a common result

Remaining evidence and scope

  • The exact signed build passed the disposable-VPS no-provider matrix: enablement, restart/doctor, capability omission, anonymous 401, and authenticated ungranted 403.
  • Run dedicated low-value Anthropic and Gemini smoke calls without retaining credential or payload data.
  • Keep streaming in L3 until usage justifies its cancellation and accounting complexity.

Do or don’t

Keep L1/L2 narrow; defer streaming

Do: Preserve the implemented secret/grant foundation and non-streaming common chat contract, then collect the remaining real-provider evidence.

Don’t: let the browser select a connection, provider host, arbitrary model, headers, or raw provider request shape.
