Ranking rule

A capability moves upward only when it strengthens the protected deployment loop, removes a demonstrated operator/deployer obstacle, or has usage evidence. Features that broaden the runtime move downward unless their isolation and recovery cost is independently funded.

Secure gateway, control plane, immutable deployment, browser SDK, KV, local blobs, realtime, bounded collections, per-app data databases, global browser identity with dashboard-role checks, CLI credential reuse, the supported non-provider tinker dev subset, dashboard project controls, agent skills, and post-V1 non-streaming LLM chat are implemented foundations. Their implemented cores are not planned work; only the named remaining evidence or deferred slices occupy ranking rows.

Scores use a 1–5 scale. Re-rank when base behavior ships or evidence changes.
