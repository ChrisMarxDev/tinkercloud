Secure static gateway

Prove the core promise with one active app, one allowlisted viewer, and a request pipeline that cannot dispatch content before authorization.

Success is measured by what an unauthorized request cannot retrieve.

Reason and value

One structural guard replaces app-specific auth

Operators and deployers can trust a private app even when its bundle is naive or AI-generated. Viewers get a simple email-code flow. This slice proves the differentiator before upload tooling or platform APIs expand the surface.

Impact5 / 5
Complexity4 / 5
Yield5 / 5

Scope

  • Strict app-host resolution.
  • Operator-created app, release, and current policy.
  • Resend OTP and host-only app session.
  • Exact email/domain/owner policy evaluation.
  • Protected file serving and SPA fallback.
  • App suspension and immediate rule/session revocation.
  • Negative route, host, path, and dependency tests.

Non-goals

  • No deployer upload or CLI deployment yet.
  • No KV, blobs, WebSockets, or backend proxy.
  • No public apps or cross-app SSO in the first proof.
  • No elaborate dashboard; only enough operator UI/CLI to seed state.

Implementation sketch

Make bypass structurally awkward

resolvedApp = gateway.resolve(canonicalHost)
endpoint = appRouter.classify(request)

if endpoint.isPreAuth:
    authOnlyRouter.dispatch(resolvedApp, endpoint)
else:
    session = appSessions.validate(resolvedApp.id, cookie)
    policy = policies.current(resolvedApp.id)
    decision = policy.evaluate(session.identity)
    authz = requireAllow(decision).context()
    protectedStaticRuntime.serve(authz, request.path)

The static runtime is not an HTTP root handler. Its public method requires an authorization context and an immutable release handle. Authorization occurs before path resolution or file opening.

Request pipeline · Test matrix

Acceptance

Evidence required

  • Anonymous HTML, JS, CSS, image, fallback, and source-map requests receive no release bytes.
  • App A’s session cannot read App B under any host/path combination.
  • Rule removal, session revoke, and app suspension deny the next request.
  • Missing/corrupt policy and unavailable database deny.
  • Traversal, symlink, Unicode, and host ambiguity corpus passes.
  • Route-registry test proves every content route is protected.

Open questions

  • Should policy be read on every request initially, or use a revision-keyed cache from day one?
  • Which OS-level beneath-root file opening approach supports the V1 Linux baseline most safely?
  • Which CSP is enforceable by default without breaking the target static app ecosystem?
  • What response distinction between unknown, suspended, and unauthorized apps is operationally useful without enabling enumeration?

Do or don’t

Do this first

Do: It produces the highest-impact proof with a bounded component set and directly retires the product’s largest risk.

Don’t: Do not pair it with self-service uploads, KV, or WebSockets. Those surfaces should consume a proven authorization context, not co-evolve with an unproven boundary.
